## 1. 전면 재설계 (9/29)
- **상황**: 1차 파이프라인(efficientnet_b0, 224 축소, 자체검증 0.67~0.75)을 통째로 삭제하고 처음부터 다시 설계.
- **원인**: 재압축·블러 augmentation이 ③(필터) 유형의 단서와 겹쳐 오히려 정확도를 깎음. 또 240장 규모에선 실험 간 변동이 커서 설정 비교 자체가 불가능.
- **해결**: 원본 해상도 조각 + DINOv3 + MoE 구조(⑫), 데이터 생성 파이프라인 신설.
- > **Lesson:** 데이터가 너무 적으면 "비교 실험"이 성립하지 않는다. 그리고 augmentation이 정답 단서를 지울 수 있다.

## 2. fp16 NaN (10/2) ★
- **상황**: DINOv3를 `.half()`로 T4에서 돌리자 첫 block부터 inf → **모든 사진이 NaN**.
- **발견**: 무작위 가중치 smoke test로는 **안 보였고**, 첫 pilot에서 Expert loss가 nan으로 나와서 발견.
- **피해 추정**: 그대로 제출했다면 NaN→0.5 방어 때문에 전부 찍는 점수(약 50%).
- **해결**: 가중치는 fp32, 연산만 `torch.autocast(fp16)`. 같은 날 SupCon 유사도 행렬의 `-1e9` fill이 fp16에서 넘치는 버그도 발견 → SupCon은 fp32 고정.
- > **Lesson:** 실제 가중치 + 실제 채점 환경(T4)으로 확인해야 보이는 버그가 있다. CPU 테스트 통과 ≠ 안전.

## 3. val 0.874인데 리더보드 0.77 (R4) ★
- **상황**: exp02 val 0.874 / AUROC 0.958 → 리더보드 0.77.
- **원인**: val은 "우리가 만든 가짜"로 구성돼 대회 가짜를 못 봄. 대회가 공개한 소수의 예시 이미지에서도 실제 사진을 가짜로 의심하는 경향이 보였다.
- **진단**: **LOGO (leave-one-generator-out)** 검증 — 한 생성기 계열을 학습에서 빼고 평가.
  - text2img 4종은 처음 봐도 거의 완벽(AUROC 0.998).
  - 실제 사진을 **편집한** 가짜는 처음 보면 balanced 0.65~0.74 → 리더보드와 같은 범위.
  - SDXL 계열을 뺀 fold 2: acc 0.543, AUROC 0.887 (본 적 있는 가짜는 0.881/0.979).
- **함정**: fold 1은 ⑥이 ④의 픽셀로 만들어져 **오염**(acc 0.997) → 일반화 증거로 쓰지 않음.
- > **Lesson:** 검증 세트가 학습 분포와 같으면 낙관적이다. "처음 보는 방식"을 흉내 내는 검증을 직접 설계해야 한다.

## 4. 도메인 갭 발견 (10/4)
- **상황**: 우리 text2img 가짜는 빨간 딸기가 주렁주렁한 범용 장면, 공개 가짜는 온실 근접(노란 번호표, 검은 트레이). 우리 실제 사진은 검은 포트·색 라벨, 공개 실제는 흰 베드형.
- **위험**: "장면이 이상하면 가짜"라는 지름길 → val 1.0이 가짜 실력이 아닐 수 있음.
- **해결**: 프롬프트 v6(근접·얕은 심도), klein 지시형 편집, 화풍판 등 약 4400장 추가 생성.

## 5. 데이터를 더 넣었더니 나빠졌다 (exp04 → 05 → 06) ★
- **exp04**: 국소 편집 2100장 전부 추가 → 기존 부분 편집 recall이 오히려 하락 (E4 recall 0.810→0.693).
- **원인**: 색·톤·JPEG·샤프닝 편집은 **학습셋에서도 recall 0~0.14**, 즉 모델이 못 배우는 양성이 약 1000장 → 라벨 노이즈처럼 작용.
- **exp05**: 배울 수 있는 1100장만 추가 → 절반만 회복(0.758). 성격이 다른 편집을 E4 하나가 맡는 혼합이 의심.
- **exp06**: 복제·국소 필터의 **family(라벨)만 E4→E5로 재배정** — 한 가지 변경으로 E4 recall 0.815 회복.
- > **Lesson:** 새 데이터를 무작정 합치면 라벨 노이즈. 한 번에 하나만 바꾸고, 이질적인 데이터는 분리해서 다룬다.

## 6. 구조 실험 7번 중 6번 무효 ★
| 실험 | 가설 | 결과 |
|---|---|---|
| exp08 | 입력 크기 불균형(표준편차 Expert 10.6 / Gate 30.9 / Common 0.22) → LayerNorm | 크기는 맞춰졌으나 val 0.868 vs 0.867. 첫 층 가중치가 스스로 조절해 사용도는 그대로 |
| exp09 | 대회 유형별 Expert 8개 | 0.865 vs 0.867, ⑥ 전용 Expert는 못 배움(0.64) |
| exp13 | Common/Expert 비중 격자(학습 없음) | 최고 +0.4%p, 잡음 수준 → 불합격 |
| exp15 | Common top-k pooling | 균형 0.797→0.787 |
| exp16 | RGB + 고주파 잔차 6채널 | 0.797→0.800 (기준 +3%p 미달), filter −2%p |
| exp17 | feature dropout 0.15 | 0.800→0.798 |
| exp18 | 흑백 FFT 스펙트럼 요약 | 0.803. noise +7.6%p만, JPEG·blur 그대로 |
- **결론**: 약한 유형의 한계는 모델 구조가 아니라 **학습에서 본 생성·편집 방식의 다양성**. 효과가 있던 변경은 라벨 재배정(exp06), 학습 방식 선택(exp11b), 문턱 이동(v5) — 전부 데이터/판정 쪽.
- 학습이 오래 걸리는 구조 실험을 리더보드 없이(마감 뒤에야 점수) 검증해야 했던 것도 제약.
- > **Lesson:** 병목을 모르고 구조부터 만지면 시간만 쓴다. 먼저 "데이터 vs 모델 어느 쪽 한계인지"를 가르는 진단을 하자.

## 7. "AI Hub 사진 = 실제" 지름길 (exp12r, 10/16) ★
- **상황**: exp11b가 AI Hub가 아닌 실제 사진을 **전부 가짜로** 판정 (외부 실제 사진 수백 장이 거의 전부 p≈1.0). 학습·검증 실제 사진이 전부 AI Hub 출처라 그때까지 숨어 있었음.
- **시도**: 다른 종류 실제만 4배 비중으로 3 stage에 추가 → 오탐 100%→0~7%로 고쳐졌지만 가짜 recall 0.866→0.814(partial_gen −11%p).
- **결정**: 폐기, v3 유지. 가중치를 30%/60%로 섞어도 중간 지점이 없었음.
- > **Lesson:** 새 실제 사진은 **같은 장면의 가짜와 짝으로** 넣어야 한다. 실제만 늘리면 모델은 "새 종류=실제 쪽으로 쏠림 / 기존 가짜 recall 하락" 사이에서 갈린다. (시간이 없어 짝지은 재학습은 못 함 → 한다면)

## 8. 문턱 이동 (v5) — 유일한 확실한 이득
- **상황**: v3 리더보드 0.83. 평가셋이 50:50이라 실제 정확도 0.99면 가짜 recall ≈ 0.67 → "가짜 1/3을 놓침".
- **방법**: 마지막 층 bias에 +ln19 → p ≥ 0.05를 가짜로. 근거는 val 처음 본 방식 균형 +1.6%p. 대회 예시 이미지는 문턱 결정에 쓰지 않음.
- **결과**: **0.83 → 0.85 (+0.02)**, val 예측과 같은 방향·비슷한 크기.
- **반면 10/4에는 불채택**: fold 하나(+0.08)만 보고 과대 해석했던 것을 fold별 최적 문턱이 다르다는 이유로 되돌렸다. 10/16엔 val 2681장 + 사전에 정한 규칙으로 재검증해 채택.
- 마감 후 v11(문턱 T=0.1)은 군집 bootstrap 95% 구간 [−0.10, +1.99]가 0을 포함해 **불채택**.

## 9. 노이즈 이상치 미규명 (10/4~6)
