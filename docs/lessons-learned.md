# 시행착오와 배운 점

각 항목: **상황 → 원인 → 해결 → 배운 점**. 수치는 [experiments.md](experiments.md) 참고.

## 1. 내부 val 0.874, 리더보드 0.77
- **원인**: val이 "내가 만든 가짜"로만 구성돼 있어 처음 보는 생성 방식을 반영하지 못했다.
- **진단**: **leave-one-generator-out (LOGO)** — 한 생성 계열을 학습에서 빼고 평가. text2img는 처음 봐도 AUROC 0.998이지만, 실제 사진을 **편집한** 가짜는 처음 보면 balanced accuracy 0.65~0.74로 리더보드와 같은 범위였다. 한 fold는 파생 관계(⑥이 ④의 픽셀로 만들어짐)로 오염돼 증거에서 제외했다.
- **배운 점**: 검증 세트가 학습 분포와 같으면 낙관적이다. "처음 보는 방식"을 흉내 내는 검증을 먼저 설계해야 한다.

## 2. 데이터를 더 넣었더니 나빠졌다 (exp04 → 06)
- 국소 편집 2,100장을 추가하자 기존 부분 편집 Expert recall이 0.81 → 0.69로 하락.
- **원인**: 색·톤·JPEG·샤프닝 편집은 학습셋에서도 recall 0~0.14 — 모델이 못 배우는 양성 약 1,000장이 label noise로 작용. 배울 수 있는 것만 넣어도 절반만 회복(성격이 다른 편집이 한 Expert에 섞임).
- **해결**: 복제·국소 필터의 family(라벨)만 다른 Expert로 재배정 → recall 0.815 회복.
- **배운 점**: 데이터 양보다 라벨의 일관성. 한 번에 하나만 바꾸고, 이질적인 데이터는 분리한다.

## 3. 구조 실험 7개 — val에서는 전부 잡음, 그런데 하나가 최종 모델이 됐다
LayerNorm 융합, 유형별 Expert 8개, Common/Expert 가중치, top-k pooling, 고주파 잔차 입력, feature dropout, FFT 스펙트럼 — 모두 내 val 기준으로는 잡음 수준(±0.005)이었고, 사전에 정한 채택 기준(처음 본 방식 균형 +3%p 이상, 실제 정확도 ≥ 0.985 등)도 통과한 것이 없었다.
- **그러나 exp16(고주파 잔차 입력)은 최종 제출 v7에 쓰였다.** val에서는 v5와 사실상 같았지만(균형 0.814 vs 0.813, acc 0.902 vs 0.901, 실제 정확도 0.983 vs 0.973) 리더보드는 **0.85 → 0.87**이었다.
- **해석 주의**: 0.02는 524장 중 약 10장이고 정확도의 표준오차가 약 1.5%p라, 이 한 번의 비교로 "고주파 입력이 효과가 있다"고 결론낼 수 없다. seed 반복이 없어서 val과 리더보드 중 어느 쪽이 잡음인지도 가릴 수 없었다. 반대로, 사전 기준만 따랐다면 이 모델은 탈락했을 것이다.
- **배운 점**: (1) 보수적인 채택 기준은 잡음에 속지 않게 해 주지만 좋은 후보도 버릴 수 있다 — 기준의 검정력을 같이 따져야 한다. (2) 검증이 구분하지 못하는 차이가 실제 평가에서는 나타났다. 평가 설계가 결론의 한계를 정한다.
- 효과가 분명했던 변경은 라벨 재배정, 학습 불가 샘플 제거, 판정 문턱 이동뿐이고 전부 **데이터·판정 쪽**이었다. 약한 유형의 한계는 구조보다 학습에서 본 생성·편집 방식의 다양성이라는 쪽에 더 무게가 실린다.

## 4. 판정 문턱 이동 — 가장 확실한 이득
평가셋이 50:50이고 실제 정확도가 0.99라서 가짜 recall은 약 0.67이었다. 마지막 층 bias에 `+ln 19`를 더해 p ≥ 0.05를 가짜로 판정 → **리더보드 0.83 → 0.85** (exp16 모델에 같은 이동을 적용한 v7은 0.87). 근거는 val 2,681장과 사전에 정한 규칙. 반면 fold 하나(+0.08)만 보고 문턱을 옮기려던 초기 시도는 fold마다 최적값이 달라 철회했고, 마감 후 더 큰 문턱(T=0.1)은 bootstrap 95% 구간이 0을 포함해 채택하지 않았다.

## 5. fp16 NaN — 안 보이는 버그
DINOv3를 `.half()`로 T4에서 돌리면 첫 block부터 overflow해 모든 출력이 NaN이 된다. 무작위 가중치 smoke test로는 재현되지 않았고, 실제 가중치로 첫 학습을 돌릴 때 loss가 nan이 되어서야 발견했다. 그대로 제출했다면 모든 출력이 0.5로 처리되어 약 50%였을 것으로 추정한다. → 가중치는 fp32, 연산만 `autocast`. 같은 날 SupCon의 `-1e9` fill이 fp16에서 넘치는 문제도 발견(SupCon은 fp32). **실제 가중치 + 실제 채점 환경으로 확인해야 한다.**

## 6. "AI Hub 사진 = 실제" 지름길 (exp12r)
학습·검증의 실제 사진이 전부 AI Hub 출처라, 모델은 다른 출처의 실제 사진을 거의 전부 가짜로 판정했다. 다른 종류 실제만 추가 학습하자 오탐은 100% → 0~7%로 줄었지만 가짜 recall이 0.866 → 0.814로 떨어져 폐기했다. **새 실제 사진은 같은 장면의 가짜와 짝으로 넣어야 한다.**

## 7. 도메인 갭
내 text2img 가짜는 범용 장면(열매가 많은 사진), 대회 가짜는 온실 근접 사진이라 "장면이 이상하면 가짜"라는 지름길이 생길 위험이 있었다. 프롬프트를 근접·얕은 심도로 바꾸고 지시형 편집 모델(FLUX.2 klein)로 약 4,400장을 추가했다. 예시 이미지를 저해상도 썸네일만 보고 "구분 불가"라고 적었다가 원본으로 보고 정정한 일도 있다. 표본이 적으면 확정 대신 "가설"로 적는다.

## 8. 끝까지 풀리지 않은 것
- **부분 생성**: recall 0.756 = 본 적 있는 방식 0.925 / 처음 본 방식 0.323. 주범은 AI 편집 모델(klein-edit)이고 편집 면적 중앙값이 6.4%라 신호 자체가 희박하다.
- **`flux_vae` 재구성**: 육안으로도 구분 불가(recall ≈ 0), val 오답의 약 31%.
- **강한 노이즈 사진의 Common CNN 특징 이상치**: fp32로 바꿔도 풀리지 않았고 원인은 규명하지 못했다(범위는 노이즈 사진의 약 1%).
- **val vs 리더보드 격차**: 최종 모델(v7)도 val 0.902 vs 리더보드 0.87.

## 9. 다음에 한다면
1. val 설계를 먼저 — 처음부터 LOGO를 기본 지표로.
2. 다양한 종류의 실제 사진 + 같은 장면에서 만든 가짜를 **짝으로** 구축.
3. 생성 방식 다양성을 일찍 — AI 편집 모델을 학습에서 빼지 않기. 21장짜리 예시 이미지로 학습 데이터를 거르지 않기(순환 논리).
4. seed 반복으로 잡음 폭을 먼저 재고 실험하기 (개선폭이 ±0.005 안이라 결론이 약했고, exp16처럼 val과 리더보드가 다른 말을 할 때 어느 쪽이 맞는지 가릴 수 없었다).
5. 마감 3일 전부터는 새 기법 금지, 안정화·제출 검증만.

> **한 줄 회고** — "내 평가가 진짜 평가와 같은가"를 먼저 의심하고 데이터 다양성에 시간을 쓰는 편이 점수가 올랐다. 그리고 내 검증이 구분하지 못하는 0.02의 차이가 실제 평가에서는 나타났다는 점이, 검증을 더 정교하게 설계해야 한다는 가장 큰 숙제로 남았다.
